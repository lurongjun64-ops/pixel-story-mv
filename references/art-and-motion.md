# 素材与动作

借鉴像素素材技能的色板锁定、精灵规格和具名动画；原生像素资产与最终高清视频分开检查。

`episode.art.palette` 是精确的六位 RGB 色表。`art.assets` 为每张 PNG 记录 id、相对路径、每格宽高、原创/来源说明以及动画。模板有一张原创 120×32 PNG：六格 20×32；两个待机格、四个走路格。读取和渲染不需要 Aseprite，也不依赖它的 MCP。

```json
{
  "id":"hero", "path":"art/hero.png",
  "frameWidth":20, "frameHeight":32,
  "source":"素材真实来源",
  "animations":{
    "idle":{"frames":[0,1],"durations":[48,6],"mode":"forward"},
    "walk":{"frames":[2,3,4,5],"durations":[6,9,6,9],"mode":"forward"}
  }
}
```

frames 从 0 开始，按行从左到右；durations 为**合成时间轴帧数**，不是毫秒。60fps 下 6 帧为 0.1 秒。`forward` 循环，`ping-pong` 首尾不重复，`hold` 到末格后停住。姿势以镜头局部帧采样，不依赖上一帧状态；改合成 fps 时一起换算 durations，以保留动作的实际速度。

动画设计要给动作留出预备、接触和恢复：走路先有支撑腿，情绪转折可短暂停顿。不要通过模糊旋转和连续拉伸让像素网格变形；需要朝向/表情时加对应格或独立标签。当前视频模板仍只调 idle/walk，增加动作时需同步场景校验允许值与动作表。

`hero.spriteId` 指定使用哪张表；`inspect/render` 先等 PNG 和字体加载，再审计：

- 半透明像素、色板之外的颜色、图幅不能整分成单元、动作索引越界：失败。
- 透明像素的 RGB 不参与色板统计。
- 孤立像素：仅提示，由角色眼睛/星点/粒子的实际意图判断；检测邻居时不跨动画单元。
- 清晰中文字体、HUD 描边、视频压缩结果不套这套 PNG 像素约束。

对新素材先 `inspect` 看 PNG 审计和三张动作关键帧，保持轮廓、衣着和相对大小一致后再做整段动画。精灵表不是任意人物动作生成器；需要新动作时仍须画素材或使用已获准的生成工具。
